EMAP-SSN Viewer

Command Line Interface (CLI) Manual & Reference Guide

This reference documents all available visual, physical, and community-clustering commands. Use the sidebar to search or filter commands dynamically. Core commands operate on the visual state in memory, while external scripts execute advanced bioinformatics algorithms and export outputs to the disk.

COMMAND help, COMMAND -h or COMMAND --help prints a command's own help in the Console; export and label also accept -?. label help needs no alignment or reference. help COMMAND prints the same help, and help alone lists every command with a one-line summary.

Expression Interpreter Syntax Rules

Overview: The Common Expression Interpreter is the underlying engine that parses text queries into mathematical selections. It is used by color, group, hide, logo, query, select, and spectrum, and allows complex, multi-layered targeting of network nodes.

Important Space Rule

Expressions must be written continuously without spaces. Spaces are strictly reserved to separate different commands, parameters, or attributes.

Targeting Modules

The interpreter recognizes six distinct targeting syntaxes:

1. Text & Wildcard Matching ("Text")

Surrounding text in double quotes searches node FASTA headers.

  • Case-Insensitive Substring: "kinase" matches any header containing kinase, in any letter case.
  • Wildcards: Supports standard glob patterns. "*A5?T*" matches any header containing 'A5', any single character, and 'T'.
2. Attribute Labels (#Label#)

Surrounding a name with hash symbols selects a topology cluster, the noise set, or a custom group; names are matched case-insensitively. Metadata is matched with {...} queries instead.

  • Clusters: #cluster_1#, #cluster_2#, etc.
  • Noise: #noise# isolates unclustered/filtered nodes (Cluster -1).
  • Custom Groups: #human# matches nodes you have manually grouped and labeled as "human".
  • Canonical Resolution: Cluster labels use their exact decimal spelling. Thus #cluster_001# may name a custom group rather than cluster 1. A label that simultaneously names an existing cluster and custom group is rejected as ambiguous.
3. Sequence Alignment Queries ([AA][Pos])

Allows targeting based on the Multiple Sequence Alignment (MSA) residue distribution.

  • Specific Amino Acid: P106 targets all nodes that have a Proline (P) at displayed position 106: reference numbering plus the session offset, or occupancy numbering when no reference is active. Residue letters are case-insensitive.
  • Grouped Amino Acids: (RHK)71 targets nodes with R, H, or K at position 71. Grouped insertion and negative positions use forms such as (RHK)71.1 and (RHK)(-1). A residue set needs at least two letters and cannot contain _; combine gaps with |, e.g. _71|(DE)71.
  • Gap Queries: _100 targets all nodes that have a gap (- or .) at displayed position 100.
  • Negative Offset Positions: Parentheses are required around negative displayed positions: use K(-1) or K(-1.1). Bare forms such as K-1 are invalid, preserving - for future expression functions.
4. External File Cross-Referencing (@Filename@)

Surrounding a filename with the @ symbol cross-references the network against a text file or FASTA file located in the Header_Lists directory. The name must be a plain file name in that directory: a name with a folder, .., a drive such as C: or a network share is refused, and the command changes nothing. The file must be UTF-8 text; entries that match no node are listed in the Console.

  • Direct Match: @my_targets.txt@ selects nodes whose full header matches a line of the file, ignoring letter case; a FASTA file contributes its > header lines. Each line is first cleaned up as headers were when the network was built (runs of spaces become one _, square brackets become parentheses), so a header copied from the original FASTA still matches. .txt is appended when the name ends in none of .txt, .fasta, .fa, .faa and .fas (any case), so a file written by select save hits.fa is read back with @hits.fa@. A header list saved under an older version as hits.fa.txt is still read by @hits.fa@ when no file named hits.fa exists (the same for .faa and .fas); the exact name wins when both exist.
  • NCBI Extraction: @[NCBI]my_targets.txt@ automatically scans the text file for standard NCBI accession codes (e.g., WP_01234.1) and matches the network headers containing those codes, ignoring surrounding text.
  • PDB Extraction: @[PDB]my_targets.txt@ performs the same extraction but for Protein Data Bank codes (e.g., 1XYZ).
5. UI Selection ($sele$)

Typing $sele$ explicitly passes the nodes you currently have highlighted/selected with your mouse in the viewer.

6. Metadata Queries ({KeyOpVal})

Allows targeting based on node metadata: the FASTA-derived numeric columns Length, kDa, pI, and GRAVY written when the layout cache is generated (caches from v0.2.0 and earlier lack them until regenerated), plus fields uploaded from Excel or CSV tables. Property names inside braces may contain only letters, digits, _, -, and ..

  • Numerical: {Length>500} targets nodes where sequence length is greater than 500. Numeric properties accept >, >=, <, <=, =, ==, and !=, plus inclusive ranges with = such as {Length=300-500}. A negative range bound must be written in parentheses, as a negative alignment position is: {GRAVY=(-1)-0} or {GRAVY=(-1.5)-(-0.5)}. A single negative value needs none: {GRAVY>=-1}. Every numeric comparison, != included, skips nodes with no value; !{Length=100} selects every other node, those included.
  • Text: {Organism=coli} targets nodes whose Organism value contains "coli", ignoring case, so = and == test containment rather than exact equality; != selects the nodes that test rejects. With a * or ? wildcard the pattern must match the whole value: {Organism=*coli} requires a value ending in "coli".
Boolean Logic Operators

You can combine any of the targeting modules above using standard Boolean logic (no spaces allowed):

  • & (AND): "Human"&#cluster_1# (Must be human AND in cluster 1).
  • | (OR): P106|A106 (Must have either Proline OR Alanine at position 106).
  • ! (NOT): !#noise# (Must NOT be noise).
  • ^ (XOR): #cluster_1#^P106 (Exclusive OR - either in cluster 1 or has Proline at 106, but not both).
  • () (Grouping): Parentheses can be used to enforce order of operations, e.g., !(#cluster_1#|#cluster_2#).
  • Precedence: ! binds tightest, then &, then ^, then |. Parenthesize when mixing operators.
Strict Context Validation

Before an expression is applied, the interpreter verifies that every referenced cluster, noise label, custom group, displayed alignment position, metadata property, and header-list file exists in the current SSN context. Metadata comparisons must also use a value and operator compatible with the property type.

If any reference or predicate is invalid, the entire submitted command is aborted and no network changes are applied. A concise error appears in the command overlay, while the Console includes the expression and available valid targets. An existing target that legitimately matches zero nodes is not an expression error.

Core Commands
zoom – Precise Camera Control
zoom <percent>

Function: Sets the camera zoom to exactly the specified percentage while preserving its current center and the canvas aspect ratio. 100% is a view 300 layout units wide (ZOOM_100_PERCENT_WIDTH in src/commands/zoom.py), and a bigger percentage is closer: 200% is a view half as wide. The % sign is optional, so zoom 200 and zoom 200% are the same, and a space may come before it. The zoom must be at most 60000% (a view 0.5 units wide) and at least the zoom that shows every node, hidden ones too, rounded down to two significant figures; that lowest zoom follows the nodes as they move and the window's shape. A zoom outside those limits is refused with both limits named. The mouse wheel, a touchpad pinch and the Zoom box beside the threshold slider stop at the same limits.

Examples
  • zoom 200
  • zoom 50%
save – Save Current View to Cache
save [filename / filename.h5]

Function: Atomically saves positions, colors, sizes, shapes, visibility, persistent node render order, clusters, groups, metadata, supported cacheable node attributes, the latest clustering parameters, and cache-manifest identity to an HDF5 layout cache. If no filename is provided, it creates the next available simple version name (for example, version_00.h5, then version_01.h5) in the active cache folder. A supplied name receives .h5 when omitted and must be a safe basename.

Examples
  • save
  • save session_layout.h5
reset – Reset Selected View to Initial States
reset <target_1> [target_2] ...

Function: Reset selected properties to their initial states. Supported targets include:

Supported Targets
  • color / colors: Reverts all node colors to the configured initial node color.
  • size / sizes: Resets all node sizes to the baseline size defined in configuration.
  • shape / shapes: Resets all nodes back to standard circular 'disc' shapes.
  • cluster / clusters: Strips all cluster labels, removes cluster UI visuals, and clears the cluster tooltip data. It also removes the subcluster_N_M groups the subcluster command generated for them and reports how many; custom groups with lookalike names, such as subcluster_0_2, are kept.
  • group / groups: Clears all custom group label sets assigned to nodes.
  • hide / hidden: Unhides all hidden nodes by setting the entire visibility mask back to True.
  • network / networks: Snaps all node positions back to the original starting layout coordinates (or the state loaded from the last .h5 save).
  • order / orders / layer / layers: Restores the persistent node rendering order to internal node-index order. Active selected or clicked nodes and their neighbors remain temporarily elevated until focus is cleared.

Validation: An unrecognized target aborts the whole command: nothing is reset, and no undo step is recorded.

Shortcuts: color reset, group reset, hide reset, and label reset are equivalent to reset colors, reset groups, reset hidden, and reset clusters. Note that label reset therefore clears every topology cluster rather than running a conservation report.

Examples
  • reset colors sizes
  • reset network hide
  • reset order
hide – Hide Selected Nodes from View
hide [expression | single | free]

Function: Hides matching nodes and their displayed edges without deleting nodes, coordinates, sequences, metadata, clusters, or groups. Visibility-aware commands exclude hidden nodes; analyses that operate on stored subsets or alignment rows retain their own documented behavior.

Arguments & Modes
  • Without arguments: Immediately hides all currently selected nodes and their connected edges.
  • With single or free: Hides all visible nodes that have no active edges at the current similarity threshold. These, like reset, take no other arguments: a word after one is refused.
  • With expression: Hides all visible nodes matching the logical expression (e.g. hide #noise#). The expression is exactly one word without spaces: more words are refused, so a quoted header with a space ("node 1") is refused rather than matching nothing.
Unhiding Nodes

To unhide nodes and restore full visibility, use the reset hide command.

Examples
  • hide
  • hide single
  • hide #noise#
undo & redo – Session History Navigation
undo [N] | redo [N]

Function: undo restores the preceding saved visual/spatial state; redo reapplies a state that was undone. Commands that call the viewer state-saving hook participate in this history. The state includes which metadata property the HUD displays (set by meta show and by spectrum), so undoing a spectrum also takes its property off the HUD. It does not include the sidebar: undo and redo leave its buttons, and whether it is open, as they are.

With N, a positive whole number, undo N restores up to N states and redo N reapplies up to N undone states. Each stops early when its history runs out and reports how many steps were done. A zero, negative, non-integer, or extra argument is refused, and nothing changes.

Examples
  • undo
  • redo
  • undo 3
  • redo 2
run – Execute Command Script
run [stop]

Function: Opens a file explorer to select a command script file (.txt or .py) and executes the commands in sequence.

Execution Details
  • Python Scripts (.py): Executed in a subprocess using the active python environment, in the script's own folder, so relative paths in the script resolve beside it. The subprocess runs in the background, so the viewer stays responsive; when it finishes, its standard output (stdout) is read and executed line-by-line in the viewer. One script runs at a time: running another while one is still running is refused.
  • Text Files (.txt): Read line-by-line. Text after // is removed, so both full-line and trailing comments are ignored.
  • Stopping Scripts: run stop ends the Python scripts the viewer is running, with every process they started, and runs none of their commands. No file explorer opens. With no script running, it succeeds and says so. Closing the viewer stops them too.
  • Infinite Loop Protection: Recursive run calls inside a script are automatically ignored to prevent viewer freezes.
  • Stops at the First Failure: The commands run in order, and the first command that fails ends the run. The commands after it are not run; the console names the command that failed and says how many were left out. A command cancelled from its own dialog ends the run in the same way.
  • Command Limit: A script may supply at most 1000 commands. A longer script is refused before any command runs.
Examples
  • run
  • run stop
console – Open the Console Window
console

Function: Opens the Console window, or brings it forward if it is already open. The Console shows everything this viewer has printed since it started, as it arrives and with the time of each line: the output of the commands, including each command's help, and every warning and error, marked in amber and red. The Console button at the foot of the sidebar and the Console link in the header of the Session card open the same window.

Console Details
  • Search and Filter: The window searches its text and steps through the matches, can be limited to warnings and errors, and can follow new lines as they arrive. It copies the selection (or all of its text) and saves the text it shows to a file.
  • What It Keeps: The window shows the last 20,000 lines. The log file it names, in temp/logs of the project folder, keeps every line of the session; it rolls over at 8 MB, and the ten latest logs of each window are kept. Buttons in the window open the log and its folder. API keys and tokens in the output are hidden, in the window and in the log.
  • Not the Command Overlay: The overlay on the canvas shows a command's short message; the Console holds everything the command printed.
  • No Window: A viewer that shows no window (headless, or hidden and not yet shown) has no Console: read its log file, or its log pages through the MCP server. A program started with --console prints to the terminal it was started from and has no Console window either.
Examples
  • console
help – List the Commands or Show Their Help
help [command]

Function: Without a command, lists every command with a one-line summary. With a command, prints that command's own help exactly as COMMAND help does, without running the command. The output goes to the Console, as every command's does.

Help Details
  • The List: The summaries are the ones the MCP server's command catalog (get_command_catalog) gives, so the list and the catalog agree, and a command added as a plugin is listed with no other change.
  • One Command: help zoom prints what zoom help prints. The name is not case-sensitive. help help, help -h and help --help print this command's own help.
  • Unknown Names: A word that is no command fails, and the Console says so in red: Error: Unknown command: NAME. Type help for the list of commands. More than one word is refused. Nothing else happens in either case.
  • Runs At Once: It changes nothing, so it runs at once, even while other commands wait.
  • The Agent: An Agent reply may not run it: the Agent's instructions already describe every command.
Examples
  • help
  • help zoom
  • help help
Alignment
reference – Reset Reference to a Different Sequence
reference [target]

Function: Dynamically changes the requested sequence used for alignment numbering and reloads the multiple sequence alignment. The <target> can be a full header, a leading identifier such as WP_0123.1 (a leading part of the header that ends at _ or |), a case-insensitive substring, or a wildcard pattern such as WP_01* or *.1 matching a network FASTA header or its identifier. An exact header or identifier takes priority, so WP_0123.1 selects WP_0123.1_protein_A rather than WP_0123.10_protein_B; otherwise, if several headers match, the first one that has a sequence in the loaded MSA is used and a warning names it. The resolved full header anchors the alignment numbering, so the reported reference is always the sequence actually used. A target whose sequence is absent from the loaded MSA is refused: the command fails and the previous reference and offset stay as they were. A configured reference that does not resolve, such as one left by loading another alignment, stays configured but inactive, and the MSA is used in reference-free occupancy mode with positions numbered sequentially. Calling reference without an argument displays the active reference, or marks the configured reference as inactive when it does not resolve. Only one target is accepted: a further argument is refused, and the reference and offset stay as they were.

Examples
  • reference
  • reference E1_RA
offset – Alignment Numbering Offset
offset [integer]

Function: Reports or changes the current session's reference-anchored alignment numbering without changing alignment columns or sequence data. Displayed labels follow displayed position = reference position + offset; insertion labels retain their decimal suffixes.

Requirements & Scope
  • Without arguments: Reports the configured offset and whether reference numbering is active.
  • With one integer: Applies a positive, negative, or zero offset. A loaded MSA and valid active reference are required.
  • Session-only: The command changes the running viewer. Configure Alignment Offset in EMAP-SSN Configuration to set the value for future sessions.
  • Affected commands: Position-aware query, label, logo, and amino-acid expressions used by color, select, group, hide, and spectrum.
  • Negative amino-acid positions: In Boolean expressions, wrap negative displayed positions in parentheses, for example K(-1), K(-1.1), or (RHK)(-1). Do not use K-1 or (RHK)-1.
Examples
  • offset
  • offset 10
  • offset -5
  • offset 0
alignment – Switch Active Alignment (MSA)
alignment [filepath]

Function: Dynamically changes the active Multiple Sequence Alignment file (.fasta or .h5) used by the viewer and reloads the MSA mapping.

Arguments
  • Without arguments: Opens a file dialog explorer to manually select a FASTA or H5 MSA file.
  • filepath: A direct absolute or relative file path to an MSA file (e.g. Input_Files/Multiple_Alignments/SeqSet_alignment.fasta).
Loading Rules & Integrity Checks

The MSA may contain all, some, or none of the sequence headers currently plotted in the viewer. Coverage is matched by exact full headers. Missing nodes remain visible and usable for topology and metadata operations, but they are excluded from alignment-dependent analyses. A partial load prints a red warning in the Console with coverage details; only unreadable or malformed alignment files cause rollback.

For amino-acid expressions, a missing alignment row is treated as unknown: neither P106 nor !P106 matches an unaligned node. Independent header, metadata, cluster, group, or file clauses can still match that node through normal Boolean logic.

Examples
  • alignment
  • alignment Input_Files/Multiple_Alignments/SeqSet_alignment.fasta
embedding – Switch Active Embedding
embedding [filepath]

Function: Dynamically changes the active protein language model embedding file (.h5) used by the viewer and matches it to the plotted nodes. Only the file's manifest is read; a command that needs per-residue embeddings reads them when it runs. Like alignment, the switch changes the running viewer only, is not an undo step, and leaves the saved Embedding Input setting as it was: configure Embedding Input in EMAP-SSN Configuration to set the file for future sessions.

Arguments
  • Without arguments: Opens a file dialog explorer in the Embedding Directory to manually select an H5 embedding file.
  • filepath: A direct absolute or relative file path to an embedding file, or a file name inside the Embedding Directory; the .h5 extension may be omitted (e.g. Embeddings/SeqSet_[esm2_t12_35M_UR50D]_embeddings.h5).
Loading Rules & Integrity Checks

The embedding may contain all, some, or none of the sequence headers currently plotted in the viewer. A node is covered when the file holds its exact full header with the identical sequence. Missing nodes, and nodes whose sequence differs from the file's, remain visible and usable for topology and metadata operations, but they are excluded from embedding-dependent analyses. The command reports how many nodes are embedded and the embedding's model, width and saving mode; a partial load also prints a red warning in the Console with coverage details. Only an unreadable, malformed or incomplete embedding file causes rollback, which restores the previous embedding.

A network built with another model than the embedding's is accepted, with a note: embedding commands use the embedding's model.

Examples
  • embedding
  • embedding Embeddings/SeqSet_[esm2_t12_35M_UR50D]_embeddings.h5
query – Alignment Position Query Tool
query [expression] <positions | frequency_logic>

Overview: Queries amino-acid distributions at explicit reference positions or searches all reference positions for residue-frequency criteria. Both modes can operate globally or on an expression-selected subset.

Prerequisites

Requires a loaded MSA with at least one row mapped to the current network. With an active reference, positions use reference-anchored numbering and the session offset. Without one, the command remains available in occupancy mode and labels retained alignment columns sequentially from 1; the offset is inactive.

Targeting & Fallbacks
  • Explicit Expression: Runs query on nodes matching the expression (e.g. #cluster_1#).
  • Mouse Selection (Fallback 1): If expression is omitted, queries the nodes currently selected in the viewer.
  • Global Network (Fallback 2): If no expression is provided and no selection exists, queries ALL nodes in the network.
  • No match: An expression that matches no node succeeds with a note that no sequences matched. Nodes that match but are not in the loaded MSA leave nothing to query, and the command fails.
Core Arguments
  • Position breakdown: Columns inside brackets, supporting lists, ranges, decimal insertion positions, and E/END for the last mapped position label, which may be an insertion or occupancy label (for example, [10,15.1,20-30,250-E]). Every negative position or range endpoint must be enclosed individually in parentheses, as in [(-1),(-1.1),0] or [(-3)-2]; bare forms such as [-1] and [-3--1] are invalid.
  • Insertions (Decimals): Insertion residues are marked using decimals (e.g., 106.1, 106.2). Querying [106-107] natively prints statistics for 106, 106.1, 106.2, and 107 in order.
  • Frequency search: Use residue or gap criteria with >, <, >=, or <=, fractions or percentages, and Boolean operators. Frequencies divide by all MSA rows mapped from the selected/global node subset, so gaps dilute residue percentages. A grouped target sums its residue frequencies, as in [(RHK)>50%]. Multi-condition searches still require parentheses around each complete comparison: [((RHK)>50%)&((DE)>20%)] or [((RHK)>50%)&(GAP<20%)]. Use GAP or _ for gaps.
  • Output: Each position prints its gap percentage and then each residue of at least 1%, largest first; X and any other symbol in the alignment count as residues. Residues under 1% are summed on one extra line, other (<1% each), so no residue present goes unreported.
Examples
  • query [10, 15, 20-30]
  • query [(-1),0,10.1]
  • query #cluster_1# [(-3)-2]
  • query P106 [150-160]
  • query {Length>500} [10-20]
  • query [K>10%]
  • query [(RHK)>50%]
  • query [((RHK)>50%)&((DE)>20%)]
  • query #cluster_1# [!(GAP>30%)&(K>5%)]
Analysis
cluster – Topology Clustering Tool
cluster [mode] [parameter] [min_size]

Overview: The cluster command partitions the currently loaded sequence similarity network into topology-derived communities that may serve as candidate subfamilies. It applies visually distinct color-coded labels generated dynamically using a custom HLS color generator that mimics the pastel look of tab20c, automatically scaling the number of distinct hues and lightness levels based on the number of clusters to color, and records these boundaries for downstream tools (such as sub-alignment and group extraction).

Arguments
  • MODE: The clustering algorithm to apply: leiden, mcl, or jaccard. Defaults to leiden.
  • PARAMETER: The primary tuning variable for the chosen algorithm (Leiden resolution, MCL inflation, or Jaccard threshold).
  • MIN_SIZE: An integer of at least 1 defining the minimum number of nodes required to form a valid cluster. Smaller communities are classified as Noise (grey) and ignored by downstream tools. Defaults to 10. A node with no edge is its own community in all three modes: a singleton cluster when MIN_SIZE is 1, and Noise when it is larger.
  • Extra arguments: Anything after MODE, PARAMETER and MIN_SIZE (or after list) is refused with an error that names the first extra argument, and nothing changes.
  • Scope and Numbering: Clustering uses every loaded edge and node, regardless of the similarity-threshold slider or hidden nodes. Retained clusters are numbered by size, so cluster_1 is the largest.
Algorithms
Leiden (Default)

Mechanism: Optimizes network modularity and density through the shared Leiden partition helper. Automatically leverages edge similarity scores as weights. Requires graspologic-native.

Parameter: Resolution (Default: 1.0). Increasing this value forces the network to fracture into smaller, more numerous clusters.

Usage: cluster leiden 1.0 10 (or simply cluster 1.0 10)

MCL (Markov Clustering)

Mechanism: Simulates random walks through the network, assuming that a random walker stays within a dense cluster rather than crossing a sparse boundary. Uses similarity scores as transition probabilities. Every node also receives a self-loop as heavy as its strongest edge (1 for a node with no edge), so the clusters do not depend on the scale of the scores: identities from 0 to 1 and −log10 E-values cluster alike. Requires markov_clustering and networkx.

Parameter: Inflation (Default: 2.0), from 1.1 to 10.0 inclusive; a value outside this range is refused before anything changes. Controls boundary granularity. Higher values (e.g. 4.0, 6.0) generally produce tighter, more numerous clusters.

Usage: cluster mcl 2.0 10

Jaccard Filter

Mechanism: Purely topological filter. Calculates the Jaccard index of the two endpoints' closed neighborhoods for every edge and cuts edges falling below the threshold. A closed neighborhood is a node's neighbors plus the node itself, so for an edge between nodes with a and b neighbors, c of them shared, the index is (c + 2) / (a + b − c). An edge outside every triangle still scores above 0, and an isolated pair or any edge of a clique scores 1. Uses numba when installed, and a slower pure-Python path otherwise.

Parameter: Threshold (Default: 0.2). A float between 0.0 and 1.0. A threshold of 0.2 means the closed neighborhoods of two connected nodes must overlap by at least 20% of their union for the edge to remain.

Usage: cluster jaccard 0.2 10

Utility Subcommands
  • cluster list: Prints a detailed report to the console detailing cluster sizes, percentages, and total noise.
Important Notes
  • Clustering is a destructive action to the visual state (overwrites node colors), but can be reverted with the undo command.
  • Running cluster replaces the current clusters, so it also removes the generated subcluster_N_M groups of the previous clustering and reports how many it removed. Custom groups with lookalike names, such as subcluster_0_2, are kept, and undo brings the removed groups back.
  • Clustering parameters are cached. Downstream sequence alignment tools automatically construct output directories named after your specific parameters (e.g., LEIDEN_1.0_Min10).
  • The command uses a dynamic color generator operating in HLS color space. It automatically scales the balance of distinct hues and lightness shades based on the number of clusters, ensuring maximum readability, visual distinction, and a clean pastel layout without requiring external dependencies.
subcluster – Cluster Subclustering Tool
subcluster <cluster_name> [mode] [param_1] [min_size] | subcluster clear

Overview: Performs subclustering on a specific topology cluster, creating custom group labels named subcluster_N_M (where N is the original cluster ID, and M is the subcluster ID). Subclusters are numbered by size, as clusters are, so subcluster_N_1 is the largest; equal sizes are ordered by their lowest member node index. The main topology-cluster labels are retained, while nodes in the target cluster are recolored by subcluster and nodes below min_size are colored gray. Running cluster again removes these generated groups, because they describe the clusters it replaces. The Console report uses the same highly saturated subcluster palette.

Arguments
  • <cluster_name>: Name of the cluster to subcluster (e.g. cluster_2, cluster_5), written as in a selection expression, without leading zeros: cluster_01 is refused and the error names cluster_1.
  • clear: Clears the generated subcluster group labels (subcluster_N_M) from the viewer session and keeps custom groups with lookalike names. It does not restore the colors applied by earlier subclustering.
  • [min_size]: (Optional) Minimum size of subclusters to keep, at least 1 (Default: 10). Smaller groups are treated as Noise. A node with no edge inside the cluster is a singleton subcluster when min_size is 1, in every mode, and Noise when it is larger. When no subcluster reaches min_size, the command reports success but changes nothing: the cluster keeps its colors and its earlier subclusters, and no undo step is added.
  • Extra arguments: Anything after the cluster name, mode, param_1 and min_size (or after clear) is refused with an error that names the first extra argument, and nothing changes.
Modes & Parameters
  • leiden (Default): Leiden Community Detection. PARAM_1 represents Resolution (Default: 1.0).
  • mcl: Markov Clustering Algorithm. PARAM_1 represents Inflation, from 1.1 to 10.0 inclusive (Default: 2.0).
  • jaccard: Topology Jaccard filtering. PARAM_1 represents Threshold (Default: 0.2).
Examples
  • subcluster cluster_2
  • subcluster cluster_2 mcl 2.0 5
  • subcluster cluster_5 leiden 1.5
  • subcluster clear
Important Notes
  • Subclustering overwrites colors within the target cluster but preserves its main cluster labels. Use undo to restore the prior state. subcluster clear removes only generated labels, whose N and M are positive integers without leading zeros. Custom groups with lookalike names, such as subcluster_0_2, subcluster_001_2, and subcluster_2_002, are kept, and subclustering cluster_2 again replaces only its generated labels. It leaves colors as they are.

Overview: While the cluster command relies on mathematics to divide the network into distinct communities, the group command allows for human-driven, manual curation. It allows you to tag specific nodes with custom metadata labels.

The most important distinction between a Cluster and a Group is exclusivity. A node can only ever belong to one Cluster at a time. However, a single node can belong to unlimited Groups simultaneously (e.g., a node can be tagged as #human#, #kinase#, and #mutant# all at once).

Canonical positive-ID subcluster_N_M names remain reserved; subcluster_0_M and leading-zero lookalikes such as subcluster_001_2 and subcluster_1_002 remain allowed as custom groups, and subcluster clear keeps them.

  • Implicit UI Targeting: Selecting nodes in the viewer with the mouse and running group [NAME] assigns that group label directly to the selection.

  • Visible Nodes Only: Like color, spectrum and select, group skips hidden nodes. An expression may match them, and so may the selection, but only visible nodes receive the label; an expression that matches only hidden nodes labels none, as one that matches nothing does. Labels a node already carries are kept when it is hidden.
Managing Groups
  • Viewing Groups: Type group list to print a statistical table showing active custom groups, node counts, and network percentages.
  • Inspecting Nodes: Left-clicking a node displays its custom groups on the second line of the tooltip header.

label – Differential Labeling & SDP Analysis
label [cluster|clusters|group|groups] [outside_max] [cluster_min] [identity] [filename] | label [cluster|clusters|group|groups] [gmax value] [cmin value] [id value] [filename]

Overview: The label command performs Differential Sequence Analysis. It is designed to identify Specificity-Determining Positions (SDPs)—amino acids that are highly conserved within a specific cluster or group, but vary across the broader protein family. It exports a rich, color-coded Microsoft Excel (.xlsx) report detailing exactly which residues define your sub-families.

Label calculation and workbook generation run in the viewer's shared background-job queue. The command captures its alignment mapping, cluster/group memberships, reference numbering, parameters, and output metadata when submitted, so later viewer changes do not alter a queued report. Label and logo jobs execute sequentially; queue and completion messages are shown in the command overlay and the Console.

Prerequisites

Because this tool analyzes sequence data rather than just network topology, it requires:
1. An active alignment (MSA) loaded in the viewer session.
2. A reference sequence set via the reference command, which anchors residue numbers.

Targets & Parameters
  • TARGET (Default: all available results): Omitting the target analyzes both topology clusters and custom groups when available. cluster/clusters retains only topology-cluster results; group/groups retains only custom-group results.
  • OUTSIDE_MAX (gmax) [Default: 40%]: Maximum frequency of a conserved residue outside the deduplicated union of all analyzed subsets where that same amino acid meets cmin at the same position. Every qualifying subset is reported when the shared outside frequency is below this value. A candidate is not reported when its exclusion union leaves no outside sequences.
  • CLUSTER_MIN (cmin) [Default: 98%]: Minimum gap-diluted amino-acid frequency inside a cluster or group. Every amino acid occurring at or above this frequency is evaluated, rather than only the dominant residue.
  • IDENTITY (id) [Default: off]: Optional sequence-redundancy threshold, accepted as a fraction or percentage such as id 0.9, id 90, or id 90%. The command calculates logo-style identity-neighbor weights once across the aligned MSA and applies them consistently to global, subset, and outside-background residue frequencies and occupancy.
  • FILENAME (optional): A single bare output workbook basename supplied as the final argument. The .xlsx extension is added when omitted; without a name, the command uses Label_Output_YYYYMMDD_HHMMSS.xlsx. Numeric or reserved-word filenames must include .xlsx to distinguish them from parameters.
  • GLOBAL CONSERVATION (fixed at 97%): Residues exceeding 97% frequency globally are reported as universally conserved. This threshold is not user-configurable.
  • Ambiguity codes: X, B, Z and J (and *, ~ and _, which the alignment loader reads as X) are never reported as conserved residues, but still count as occupied positions, so frequencies and occupancy keep the same denominators. U and O are reported as residues.

Thresholds are finite numbers written as fractions (0.4) or percentages (40 or 40%): a trailing % always means percent, so 0.5% is half a percent, and a bare value above 1 is a percentage. The first two positional numbers remain gmax and cmin; an optional third positional number is identity (for example, label 0.4 0.9 90%). Use id VALUE to enable identity weighting while retaining default or keyword-based gmax/cmin. Do not mix positional numbers after keyword parameters.

Understanding the Excel Output

Output is written beneath the configured Analysis Results directory (by default, Analysis_Results/Cluster_Label/) and contains three worksheets:

  • Meta Data: Records network, alignment, clustering, and label parameters. A compact Statistics value reports Aligned N of N | Excluded N | Effective N; without identity reweighting, Effective equals the aligned count.
  • Subset Stats (SDP Matrix): Lists clusters/groups in rows and alignment positions in columns. Displays conserved amino acids colored by gap-occupancy. If multiple amino acids independently pass at one subset-position, the cell joins them in descending subset-frequency order, for example Y120 | F120.
  • Occupancy Stats: Provides gap-occupancy percentages for every position, highlighted in green. Useful for identifying insertion/deletion variations across subfamilies.

When identity weighting is enabled, both statistics sheets add an Effective N column. Raw Count, Percent, and sequence-length statistics remain unweighted. Without an identity value, the workbook layout and calculations retain their historical behavior.

Examples
  • label
  • label 30% 90%
  • label id 90%
  • label 0.4 0.9 90% weighted_report
  • label groups cmin 90%
  • label groups group_report

esmfold – Local or Biohub ESM3 Structure Prediction external
esmfold [large] [multi] | esmfold stop | esmfold help

Overview: The esmfold command predicts protein structures with ESM3 and opens them in a web-based Mol* 3D structure visualizer. Without the large modifier, it runs the EvolutionaryScale ESM3 1.4B open-weights model (biohub/esm3-sm-open-v1) locally and writes backbone-coordinate PDB files containing N, Cα, C, and geometrically inferred carbonyl O atoms. Adding large sends the prediction to the ESM3 model configured for Biohub—currently esm3-large-2024-03 (98B)—whose current output includes side-chain heavy-atom coordinates. Neither mode adds hydrogen atoms. The command also registers the "Fold View" sidebar button; the sidebar opens when the button is new, and later runs leave it open or closed as you left it.

Core Arguments
  • No Arguments: Predicts one selected node locally with ESM3 1.4B and produces a backbone-coordinate PDB file. With no selection, folds the node you last clicked and says so (“Nothing is selected, so the last clicked node is folded: <node>.”); with no node clicked either, registers the Fold View button and opens Mol* without launching a prediction. If several nodes are selected, the command fails unless multi is given.
  • multi: Processes all currently selected nodes one after another in one background job. It uses the local backbone-only mode unless combined with large.
  • large: Predicts one selected node remotely using the model in src/resources/Biohub_API.json, currently ESM3 Large 98B. The current Biohub output includes side-chain heavy atoms, unlike the local backbone-only output. Combine with multi in either order for a sequential remote batch.
  • stop: Ends the fold that is running, with every process it started, and takes the folds that wait out of the line; nothing else. Structures already saved are kept, a half-written one is deleted, and each fold's job is reported cancelled. With none running or waiting, it succeeds and says so. A request that holds only stop commands runs at once, even while the esmfold request it ends is still waiting for its worker.
  • help: Prints CLI help and usage instructions.
Hardware & System Integration
  • Local Acceleration: Local inference automatically selects among CUDA/ROCm, Intel XPU, Apple Metal (MPS), and CPU devices supported by the installed runtime.
  • Biohub Mode: Remote inference bypasses local hardware selection and keeps local and remote PDB files separate. It needs your Biohub API token, saved in the Biohub API settings file (or given as the ESM_API_KEY environment variable). The worker has no window to ask in, so when no token is saved the Viewer asks for it in a dialog (typed hidden) before the fold is queued, and saves it; cancelling queues nothing. If Biohub rejects the saved token while folding, the Viewer asks for a replacement, once, and the structures not yet folded go on with it. A Viewer with no window cannot ask, and the command fails. The token is never taken from a command and is shown and logged nowhere.
  • Worker Process: Each fold is a job of the Viewer’s background job scheduler, in a Folding line of its own beside the line of the file jobs (label, logo, print). The worker runs in the background without any window, so the desktop Viewer stays responsive, and writes its output to a log file that the command’s result names; a fold that failed keeps a row with its reason, in the Session card and on the Fold View page, and an Open log button that opens that log in your text viewer. Only one worker runs at a time, so that a second model is never loaded into GPU memory; a fold given while another runs is not refused but waits its turn, and the result gives its place in the line. A node that another fold is to write, or is writing, is left out of the new one and the result names the job that holds it; when no node is left, the command is refused. The Background jobs section of the Viewer’s Session card lists the folds: a waiting fold can be moved or removed, and the running one stopped, as can jobs and esmfold stop. A Viewer with no window (a headless one, or a hidden one whose window is not shown) opens no Mol* page: the command’s result names the address the Mol* page is served at. Closing the Viewer ends the running worker. Opening Mol* with nothing selected or clicked is not queued.
  • Mol* Interface: Hosts a web server that loads the predicted structure in a rich interactive 3D viewer.
  • Per-Residue Data: While an alignment is loaded, each structure folded for a node that the alignment holds gets a file beside its PDB, <pdb name>.residues.json, with two values for every residue, computed from the whole loaded alignment (hidden nodes included): Information Content, the column height the logo command draws by default, as a percentage of log2(20) = 4.32 bits; and Residue Agreement, the share of the aligned sequences with a standard amino acid in the column that have this protein’s amino acid (this protein counts too). The file also names the alignment, identifies the loaded rows and gives each residue’s alignment column. A node the alignment lacks or holds under another sequence gets no file, and neither does any node when no alignment is loaded; the command’s result says which. The structure viewer page reads these files.
Examples
  • esmfold
  • esmfold multi
  • esmfold large
  • esmfold large multi
  • esmfold stop
  • esmfold help

print – Image Export & Snapshot Tool
print [filename] [modifiers]

Overview: The print command exports the network view while temporarily suppressing interactive overlays such as instructions, zoom/tooltip text, hidden-node count, metadata HUD, and command-console text. PNG captures also leave out the hover colour of the node under the mouse and the halo of the clicked node, which return afterwards; selection borders stay. Images are routed beneath the configured Analysis Results directory (by default, Analysis_Results/Saved_Images/); a filename must be one word and a plain file name, not a path, and receives .png or .svg when missing. A name ending in .svg selects SVG as the svg modifier does (so it cannot be combined with transparent or full), and a name ending in .png cannot be combined with svg; a bare .png or .svg is not a name and is refused. A second word that is not a modifier is refused, so a mistyped modifier is never saved as part of the name. An explicit name replaces an existing file of that name, and the report says so; the automatic timestamped name never replaces a file. Every PNG mode automatically trims background-only margins after rendering while retaining a fixed 20-pixel border around the rendered content; an SVG is framed the same way, with a border of 20 of the PNG's pixels around the network as drawn.

The picture is taken when the command runs: the view, every tile of a full PNG, or the nodes and edges an SVG draws. Trimming and encoding the PNG, or writing the SVG, then run in the viewer's shared background-job queue, the one label and logo use, so the viewer stays usable and later changes do not alter the file. The queue reports when the file is saved and opens its folder. A name a queued job is still to write is refused, and timestamped names skip the names queued jobs hold.

Modifiers
  • transparent: Removes the solid background, making the output PNG transparent.
  • full: Bypasses OpenGL camera edge-clipping. Renders the network tile by tile off screen, without moving the view, and stitches the tiles into a massive, ultra-high-resolution PNG. Keyboard and mouse input waits while the tiles are drawn, and resizing the window cancels the capture. An image of more than 1000 megapixels (MAX_FULL_IMAGE_MEGAPIXELS in src/commands/print.py) is refused before any tile is drawn, naming the largest zoom N that fits; making the image takes about 4 bytes of memory per pixel, 7 with transparency. Can be combined with transparency.
  • svg: Writes a layered Scalable Vector Graphic of the network as displayed, without shutting down the OpenGL viewer: visible nodes and the edges shown on screen (the similarity-threshold and manifold-layout (UMAP or PaCMAP) filters apply), in the configured edge and node-boundary colors. Text labels are not included. Node sizes and line widths follow the current zoom, so the SVG keeps the proportions shown on screen. It draws what a PNG of the view shows: each marker's shape as on screen, and node outlines (selection borders too) and edges as wide as the screen draws them, so a thin outline is about 1.7 device pixels wide and edges are whole device pixels; on a high-DPI display both come out thinner beside the nodes. Cannot be combined with transparent or full.
  • zoom N: Only with full or svg, anywhere among the modifiers. Draws at the scale zoom N would set, a zoom of N percent as in the Viewer's Zoom box (the % sign is optional, and a space may come before it), without moving the view; N must be a positive zoom the view can draw, and the zoom command's limits do not apply. With full, node sizes stay in screen pixels and a bigger N gives a larger image; an image whose longest side is under 1000 px is still saved, with a warning. With svg, node sizes and line widths are written as at that zoom. Refused with a plain PNG. The word after zoom is always read as N, so a file named zoom is written zoom.png.

logo – Sequence Logo Generator
logo [expression] <positions> [filename] [mode] [gap_mode] [color_scheme] [identity]

Overview: The logo command generates publication-ready sequence logos (in vector .svg or transparent .png format) to visually represent amino acid conservation across a specific subset of your network. By combining this tool with the Common Expression Interpreter, you can instantly compare the binding motifs, active sites, or structural variations of different protein sub-families directly from the viewer.

Logo calculation and file generation run in the viewer's shared background-job queue so the viewer remains interactive. The selected aligned sequences, mapped positions, reference, and rendering options are captured when the command is submitted. Exact redundancy calculations use a balanced parallel Numba kernel when available and fall back to NumPy otherwise. Label and logo jobs execute sequentially; queue and completion messages are shown in the command overlay and the Console.

Prerequisites

Requires a loaded MSA with at least one row mapped to the current network. With an active reference, positions use reference-anchored numbering and the session offset. Without one, the command uses the occupancy-mode labels numbered sequentially from 1, the same positions query reports, and the axis reads “occupancy numbering”.

Core Arguments
  • [POSITIONS] (Required): Comma-separated reference positions or integer ranges in brackets (e.g. [10-25]). Fractional insertion positions, representing retained alignment columns where the reference has a gap, may be listed explicitly (e.g. [10,10.1,10.2,11]). Every negative position or range endpoint must be enclosed individually in parentheses, as in [(-1),0,1] or [(-3)-(-1)]; bare negative positions are invalid. Integer ranges retain integer-only behavior. Spaces after commas are accepted ([1, 2]). Write each range from lower to higher ([10-25], not [25-10]).
  • FILENAME: Output name, which must end in .svg or .png; without one a timestamped logo_YYYYMMDD_HHMMSS.svg is created. Saved beneath the configured Analysis Results directory (by default, Analysis_Results/Sequence_Logos/). A last remaining word without that extension is read as part of the expression, so a mistyped keyword such as nogap is refused rather than used as a filename: write logo $sele$ [10-20] my_logo.svg.
  • MODE: bits (Default - Shannon Information Content) or pcts (Percentages).
  • GAP_MODE: with_gap (Default - scales stack height by occupancy) or no_gap (ignores gaps).
  • COLOR_SCHEME: Preset color scheme. Defaults to chemistry. Presets: chemistry, classic, grays, base_pairing, colorblind_safe, charge, hydrophobicity, etc.
  • IDENTITY: Optional sequence-redundancy threshold. Reweighting is disabled when omitted. 0.9, 90, and 90% are equivalent. Weighted amino-acid frequencies apply to percentage and bits modes; bits mode also uses the effective sample size for its small-sample correction. The correction at each position counts only the sequences that have a residue there (gaps are not counted), or with IDENTITY their summed weight.
Outcomes & Limits
  • No match: An expression that matches no node succeeds with a note and queues no job. Nodes that match but are not in the loaded MSA leave nothing to analyse, and the command fails.
  • PNG size: A PNG is drawn as one 600 dpi image, so a PNG logo of more than a few hundred positions is refused before it is queued, and the error names the exact limit. Use an .svg filename, which has no such limit, or fewer positions.
  • Axis label: The x axis names the reference header the positions are numbered against. A header too long for the axis is cut short with an ellipsis, so it never widens the image.
Examples
  • logo [10-20]
  • logo [10,10.1,10.2,11]
  • logo [(-1),0,1]
  • logo #cluster_1# [(-3)-(-1)] pcts
  • logo #cluster_1# [1,5] pcts no_gap
  • logo [10-20] color=charge
  • logo #cluster_1# [1,5] bits 90%
LLM Agent
agent – LLM Agent CLI Portal core
agent [<Model Custom Name> / off / deactivate / "<message>"]

Overview: The agent command provides a CLI portal to interact with the LLM Agent. You can open the Agent browser-based UI, activate or deactivate model cards, and send direct queries to the agent from the console.

Core Arguments
  • No Arguments: Opens /agent.html on the viewer's active web server in the default browser. The host and port come from the running viewer rather than a fixed URL.
  • <Model Custom Name> (Mandatory Brackets): Enclosed in <> brackets, this activates the agent and loads the specified model custom name (e.g. agent <Gemini API>).
  • off / deactivate: Deactivates the LLM agent and unloads the active model.
  • "message" / message: Forwards the query directly to the LLM agent. If the agent isn't turned on, it will automatically load the first model card in your list. The message and its answer appear in the Agent page as if typed there. A command in the reply that needs your approval (one that writes or imports files, opens a dialog or spends credit) waits for Run or Discard in the page, which opens if the Viewer shows windows; in a Viewer with no window and no open page it is refused at once.
  • A model card on another computer: The first time agent <Model Custom Name> or a message would switch on a card whose server is not on this computer, the command fails and the Agent page shows what the card receives; nothing is sent before you press Continue there, once for each card address.
Examples
  • agent
  • agent <Ollama (Local)>
  • agent off
  • agent "make cluster 1 green"
